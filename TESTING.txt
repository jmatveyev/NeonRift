VISUAL IMPLEMENTATION BOUNDARY
==============================
The 1.4 overhaul is a Canvas 2D presentation layer, not a replacement game
engine. It adds:
- Multi-depth stars and nebula depth.
- Deterministic sector debris/fractures/architecture without consuming gameplay
  RNG.
- Detailed ship/enemy overlays, engine/motion trails, and energy cores.
- Stage-specific boss geometry and orbiting elements.
- Projectile trails, hostile-shot halos, particle streaks, kill bursts, and
  shockwaves.
- Camera lead/kick/zoom response, Overdrive feedback, sector pulses, low-hull
  edge lighting, and limited desktop chromatic edge response.
- Cinematic boss stings.
- Upgraded hangar, mode cards, upgrades, HUD, abilities, boss HUD, panels, and
  callsign prompt styling.

Performance-sensitive effects are deliberately reduced on coarse-pointer/touch
devices. Reduced-motion preferences also suppress or reduce animated presentation
where appropriate. Combat logic, score rules, run RNG, difficulty, and balance
are not intentionally modified by the visual layer.

QA-ONLY DIAGNOSTICS
===================
The normal production URL keeps renderer/game-state internals closed over as
before. The 1.4 assembler exposes a minimal rendering diagnostics bridge only
when the explicit `?test` QA surface is present. This lets Playwright force visual
sectors, render frames, inspect visual budgets, and measure Canvas output without
making those internals part of ordinary gameplay.

BACKEND / LEADERBOARD SECURITY
==============================
Neon Rift 1.4 does not require a Supabase schema change. It retains the hardened
1.3.1 backend:
- Anonymous clients can read `runs` but cannot directly insert/update/delete.
- Backend-only player/session/telemetry/rate-limit tables remain inaccessible.
- Score writes go through the `game-session` Edge Function.
- Standard, Endless, and Daily remain separate run modes.
- Standard/Daily use the nine-sector objective; Endless can exceed sector 9 and
  cannot submit a victory state.

The 1.4 client sends game version 1.4.0 through the existing managed-session path.
No secret or service-role credential is present in browser code.

LIMITATIONS
===========
The automated suite is strong regression coverage, not a claim that every visual
choice looks identical on every physical display. Headless Chromium validates
rendered output, mode-specific pixel changes, layouts, visual state, and gameplay
invariants, but it does not substitute for subjective inspection on physical
iPhone/Android hardware or Safari/WebKit.

The game remains client-authoritative for competition. The managed backend is
hardened against casual direct-database score fabrication, but it is not a fully
server-simulated or cryptographically provable esports environment.
